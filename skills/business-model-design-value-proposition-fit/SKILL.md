# Value-proposition fit decision rules

Decision rules for constructing a Value Proposition Canvas (VPC) and
judging whether a value proposition has achieved fit. Research trail:
layer 1 (Strategyzer primary sourcing on the VPC and its named failure
modes).

## Trigger

Apply this skill when building a VPC's Customer Profile or Value Map
for a single segment, judging whether a value proposition has achieved
fit against evidence, or checking a value proposition for a named
fit-validation failure mode.

## Procedure

1. Fill the Customer Profile before the Value Map, one segment at a
   time, never blending segments (rule 1).
2. Capture jobs at both functional and social/emotional levels
   (rule 2).
3. Treat fit as an iterative, evidence-based state, not a one-time
   fill (rule 3).
4. Check against solution-first bias when building the Value Map
   (rule 4).
5. Check against the comprehensive-coverage trap when prioritizing
   which jobs/pains/gains to address (rule 5).

## Output shape

A Customer Profile and Value Map for one named segment, a fit verdict
stated against real customer evidence (not a one-time fill), and an
explicit check against the named failure modes before the value
proposition is treated as validated.

## Rules

1. Fill the Customer Profile (jobs, pains, gains) for ONE segment at a
   time before designing the Value Map (products & services, pain
   relievers, gain creators) for that same segment — never the
   reverse, and never blend two segments (e.g. payer vs. user) into
   one profile; blending segments produces a Value Map that fits
   neither segment precisely.
   source: https://www.strategyzer.com/library/5-common-mistakes-to-avoid-when-using-the-value-proposition-canvas

2. When capturing jobs on the Customer Profile, include social and
   emotional jobs, not only functional tasks — a job captured only at
   the functional level (e.g. "get from A to B") misses the
   social/emotional job (e.g. "look successful doing it") that often
   drives the actual purchase decision, and this is a named
   completeness failure mode when jobs are captured too narrowly.
   source: https://www.strategyzer.com/library/5-common-mistakes-to-avoid-when-using-the-value-proposition-canvas

3. Treat "fit" as an iterative, evidence-based state — the Value Map
   adjusted against real customer evidence — not a one-time
   fill-and-done artifact; a Value Map that has not been revised since
   its first draft has not yet been validated against evidence,
   regardless of how complete it looks.
   source: https://www.strategyzer.com/library/the-value-proposition-canvas

4. When building the Value Map, check for solution-first bias —
   cherry-picking jobs/pains the existing solution already covers
   instead of starting from the Customer Profile's actual jobs, pains,
   and gains — because a Value Map built backward from an existing
   solution validates the solution, not the fit.
   source: https://www.strategyzer.com/library/5-common-mistakes-to-avoid-when-using-the-value-proposition-canvas

5. **[removal]** When prioritizing which jobs, pains, and gains the
   Value Map addresses, check against the "comprehensive coverage
   trap" — attempting to address every job instead of prioritizing the
   top few — and cut coverage down to the highest-priority items
   rather than spreading the Value Map thin across all of them; a
   value proposition that tries to address everything differentiates
   on nothing.
   source: https://www.strategyzer.com/library/5-common-mistakes-to-avoid-when-using-the-value-proposition-canvas
