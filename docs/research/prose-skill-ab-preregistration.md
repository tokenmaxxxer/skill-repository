# Pre-registration — A/B test of the technical-writing skill

**Status: FROZEN on commit. Date stamp: 2026-07-16.**

This document is registered BEFORE the research rounds run and BEFORE any rule text exists. That ordering is the operative definition of validity for this test, not a formality — see Gate 0. Any metric proposed after the rule set exists is compliance-only, permanently, with no appeal.

It extends the six-field form in `plugins/core/skills/hypothesis-testing/SKILL.md:76-85`, which is necessary but not sufficient for a test whose two obvious graders are each compromised.

---

## Step 1 — Scope gate

**Is a genuine kill/persist decision still open?** Yes. The option to not proceed is real: we can ship nothing, keep `readable-prose` as-is, or ship a rule set labeled unverified. Nothing is funded, committed, or contractually locked.

**Is there an observable outcome that could settle it?** Yes, for one specific question: does the *content* of the rules change generated text more than a length-matched generic instruction does. This is observable and falsifiable.

**Is there a theory, or just a task?** There is a theory, stated in Step 2, and it can be wrong.

Gate result: **proceed** — but with the scope narrowed by the ceiling in the next section.

## The ceiling — what this test can and cannot establish

Established by prior adversarially-verified research (`/home/jwjung/fictions/prose_research/`, reports 16 and 17); treat as given.

- 31 prompting strategies all land on a near-identical response-length/accuracy trade-off curve (arXiv:2503.01141). Real prompts achieved 1.16–1.47× compression where the theoretical room was 3.2–11.2×.
- Multi-hop accuracy caps near 60% even when every single-hop fact is correct (arXiv:2506.02000).
- Depth collapses with reasoning depth under a *fixed* prompt (Multi-LogiEval, arXiv:2406.17169): ~68% at d1 → ~43% at d5.

**Prompting raises the floor; it does not raise the ceiling.** A skill is a prompt. Therefore this test is not permitted to ask whether the skill makes writing *deep*. It asks whether the skill suppresses specific defect patterns without suppressing their legitimate uses.

## Step 2 — Theory

> **We believe** an operationalized, mode-routed rule set injected as a skill (X)
> **will produce** fewer illicit instances of named prose-defect patterns, without suppressing those patterns' legitimate uses (Y),
> **for** Korean and English documents generated by Claude in this organization (Z),
> **because** the defects are alignment-induced *defaults* — reward-model length bias, format bias (injecting 0.7% format-biased preference data raises list-preference win-rate 51%→77.5%, arXiv:2409.11704), and typicality/fluency bias — and a default is by definition overridable by an explicit instruction, even where the underlying capability ceiling is not.

The mechanism clause is what makes this falsifiable. If the defects are *not* overridable defaults — if they are capability limits, or if any instruction of comparable length moves them equally — the theory is wrong and the rule content is inert.

## Step 3 — Hypotheses

| # | Hypothesis | Metric | Direction / threshold | Measured where |
|---|---|---|---|---|
| **H1** (primary) | The rules' *content* — not their mere presence — suppresses illicit patterns | Illicit-instance count per document, per pattern | ON < PLACEBO by ≥30% relative reduction, in ≥60% of matched prompt pairs | Stratum A + C documents |
| **H2** (harm, co-primary) | The rules do not suppress legitimate uses of the same patterns | Binary presence of the pre-specified proposition the licit instance must carry | ON retains ≥80% of the licit propositions that PLACEBO retains | Stratum B documents |
| **H3** (manipulation check) | The model reads the rules at all | Illicit-instance count per document | ON < OFF, any reduction ≥30% in ≥60% of pairs | Stratum A documents |

**H1 is the one that can kill the skill.** If ON beats OFF but not PLACEBO, we measured "an instruction is present" and the rule content is inert. This hypothesis is registered now, before any rules exist to be attached to.

Falsifiability check: H1 fails if the ON/PLACEBO difference is below threshold. H2 fails if licit retention drops below floor. H3 fails if the model ignores the skill. Each has a conceivable result that counts against it.

## Step 4 — Registration

### (a)–(f), the base form

| Field | Content |
|---|---|
| (a) Hypothesis | H1, H2, H3 above |
| (b) Test design | 3-arm matched-pairs generation study, documents scored by frozen detectors + pre-specified proposition checks |
| (c) Metric and window | Illicit-instance counts and licit-proposition presence, measured once on a single frozen generation batch |
| (d) Threshold and decision rule | Per-rule routing table below |
| (e) Sample size | Fixed below; no additions after results are seen |
| (f) Date stamp | 2026-07-16, before research rounds and before rule authoring |

### Field 1 — Frozen elicitation set

Committed as a separate file with a content hash before the skill text exists. Three strata:

- **Stratum A — neutral explanatory prompts.** 20 prompts (10 Korean, 10 English) requesting technical explanation with no style guidance. These carry H1 and H3.
- **Stratum B — licit-use prompts.** ≥5 per banned pattern, each annotated with the *exact proposition* its correct instance must carry. These carry H2 and are **mandatory for any rule that has a licit use**. Slots for translationese patterns are filled after the research round; the false-alarm ceiling (80%) is fixed now and may not move.
- **Stratum C — depth-demanding prompts.** 10 prompts requiring mechanism plus failure condition. Bundle-level only; no per-rule claim will ever be made from these.

Generation: n=3 per prompt per arm. Stratum A yields 20 × 3 arms × 3 = 180 documents.

### Field 2 — Base-rate pilot

OFF-arm, n=20 on Stratum A, run and committed **before the skill text exists**. Produces the Gate-1 denominators. May not be re-run after the fact.

### Field 3 — Arms

- **ON** — the skill at a named commit.
- **OFF** — no skill.
- **PLACEBO** — a length-matched, plausible generic instruction at the same token count (±10%), e.g. "명확하고 정확한 한국어로, 근거를 갖춰 쓰라" expanded to match. **The primary contrast is ON vs PLACEBO, not ON vs OFF.**

Without the placebo arm, rule content is confounded with prompt length and attention allocation.

### Field 4 — Generation protocol

Model pinned to `claude-sonnet-5` (the tier that produces documents in this org per `core:model-routing`; generalization to other tiers is untested and will be stated as a limit). Temperature and top_p fixed and recorded. Generation order randomized; arm assignment via a committed seed. **Generator and grader must not be the same instance.**

### Field 5 — Design and unit of analysis

Matched pairs on prompt. **Unit of analysis = document.** Sentences within a document are not independent; sentence-level analysis would manufacture significance. Clustering by prompt is pre-registered.

### Field 5b — Mode-dependent patterns may not be scored on a mixed stratum

**General rule, registered now:** a pattern whose licitness depends on document type may NOT be scored as a single illicit count across a document-type-mixed stratum. It is scored per implied document type using the Stratum A annotations, or not at all.

Violating this produces a metric that punishes success. Worked example, identified before the pilot: Stratum A contains four reference-type prompts (A05, A06, A15, A16 — restartPolicy values, pagination parameters, `ls` options, exit codes). Bullets and tables are the *correct* output there. A single Stratum-A-wide bullet count would score a working mode-router as failing, and would score a naive skill that bans bullets everywhere as succeeding — rewarding exactly the defect this project exists to remove.

Registered consequences:
- Reference-type Stratum A documents (A05, A06, A15, A16) are scored for bullet/개조식 patterns as **licit-use** (harm screen, H2 logic), never as illicit instances.
- Illicit bullet counts are computed only over the explanation/conceptual and design/decision subsets (A07–A10, A17–A20).
- Any rule the research produces whose licitness turns on document type inherits this treatment automatically, without renegotiation.
- Rules 번호 교차참조 and 메타공지 are provisionally flagged as mode-dependent pending the final rule list; the contradiction audit (Field 12) resolves their status before generation.

### Field 6 — Per-rule block (slots frozen now, rule text filled after research)

Each rule gets: rule id · exact rule text · target feature · detector spec (exact regex, or extractor prompt + model + temp 0, versioned) · licit-use prompt ids · hypothesis direction · minimum effect size on the count scale · false-alarm ceiling · kill rule as a numeric inequality.

### Field 7 — Extractor validation

Any LLM-as-extractor detector requires human agreement on a pre-specified subsample, **κ ≥ 0.6**. Pre-committed consequence of failure: the extractor is **void** and the rule's status becomes **untested** — never "passed."

LLM-as-extractor (locate every analogy; locate any prior operational definition of its target term; check order) is a bounded classification task with a checkable answer. It is a different instrument from LLM-as-judge, whose fluency channel lives in preference and quality judgments. That distinction is load-bearing and may not be blurred.

**Partial-proposition scoring, fixed now.** Some licit-use propositions are multi-clause and can be answered correctly but incompletely (e.g. B05: force-pushed commits are recoverable via local reflog but subject to the remote's GC grace window — a hedged answer may carry one clause and not the other). The extractor scores the proposition as present only if every clause listed in the elicitation set's `Required proposition` field is present. Partial credit is not available. This is registered before scoring so it cannot be loosened for a rule that needs the help.

### Field 8 — Blinding

The scrambling script is committed. Arm labels are stripped before scoring. A non-author adjudicates where possible; where impossible, the limitation is written here now, while it is cheap to write: **the skill's author is also its grader for the mechanical detectors, and no reliability estimate exists for that path.**

### Field 9 — Analysis plan

Multiple-comparison correction: **Holm**. At k≈20 rules and α=.05, roughly one spuriously "verified" rule is the expected yield of doing nothing. Zero counts and refused/missing generations are handled by pre-specified rules, not by judgment at analysis time.

### Field 10 — Stopping rule

N fixed above. No peeking. No adding documents after seeing results. No dropping prompts that "didn't work."

### Field 11 — Decision table

| Outcome | Action |
|---|---|
| H3 fails (model ignores rule) | **Kill** — the rule costs context for nothing |
| H2 fails (licit suppression below floor) | **Kill** — harm is not shippable |
| H1 fails, H2 and H3 pass | **Ship labeled "compliance-verified, content-inert vs. placebo"** — and reconsider whether the rule earns its context |
| H1, H2, H3 pass | **Ship labeled "compliance-verified, benefit unverified"** |
| Rule has a licit use but no false-alarm arm was run | **Do not ship** — its harm is unbounded |

A revised rule is a **new** pre-registration and may not be scored against this data.

### Field 12 — Contradiction audit (before generation)

Interacting rules must be declared as a set up front, or ablation attributes effects to the wrong rule. One contradiction is already identified in the design:

- **"State the assumed reader knowledge level"** vs. **"ban meta-announcements (이 글에서는 ~를 살펴본다)"** — a model satisfying the first with "이 글은 X를 아는 독자를 가정한다" produces exactly the shape the second bans. Declared as an interacting set; no individual claim will be made about either.

The full audit runs against the final rule list before generation.

### Field 13 — Whole-skill falsification condition

**The skill is abandoned rather than revised if ON fails to beat PLACEBO on every Gate-1-passing compliance metric.** That result means the rule content does nothing that any instruction of the same length would not do.

### Field 14 — Null-reporting commitment

Every rule tested is recorded with its result in the shipped skill's documentation, **killed ones included**. Without this, failed rules quietly disappear and the survivors look like a verified set.

### Field 15 — Claim ceiling

Fixed now, before there is any reason to want it softer.

- **Permitted**: "Rule R reduces pattern P by X% relative to a length-matched generic instruction, without suppressing licit uses of P below the registered floor."
- **Forbidden**: "verified to improve prose quality." "Verified to make writing clearer/deeper/more readable." "A/B verified" without the qualifier. Any claim that this test measured comprehension, transfer, or reader outcome — **it did not, by design.**

The honest expected output of this entire exercise is a skill labeled **"compliance-verified; benefit unverified at rule level."** That was priced in before the first document was generated.

## Rule triage — applied mechanically at registration time

- **Gate 0 — Circularity.** Was the metric's full specification frozen before the rule existed, without knowledge of the rule set? Enforced by *ordering*: freeze metrics in a commit → run research → write rules. Fails → compliance-only, no appeal.
- **Gate 1 — Base rate.** In the OFF-arm pilot (n=20), does the target feature occur in ≥30% of documents? Fails → not testable (floor effect, no power). Fix the elicitation set or drop the rule.
- **Gate 2 — Licit use.** Can ≥5 prompts be built where the feature's correct instance is the right output? Yes → false-alarm arm mandatory. No licit use anywhere → pure lexical ban; grep is a valid, honest instrument.
- **Gate 3 — Identifiability.** Is an ablation arm budgeted for this rule? No → no individual kill decision; the rule joins the bundle.

**Routing:** passes 0+1+3 → individual kill line permitted. Fails 0, passes 1+2 → compliance + false-alarm only. Fails 1 → do not test, do not ship. Has licit uses but no false-alarm arm → **do not ship**. Fails 3 → bundle membership; no individual claim, ever.

**Registered prediction:** every depth rule fails Gate 0 or Gate 3; every surface rule fails Gate 0. Recorded here so it cannot be presented as a surprise later.

## What was rejected as an instrument, and why

- **Held-out pattern split** (the original proposal) — **rejected as an inference carrier.** "Learned the principle" and "pattern-matched more broadly" predict the same observation, so the two hypotheses are not discriminable. Where they do diverge — a held-out item outside every stated principle's extension — suppression is a *harm* signal, not success. Retained only as a demoted manipulation check, with a blind coverage adjudication run before any generation data exists.
- **Forced-choice pairwise preference (LLM or human)** — **rejected as a benefit measure.** This is the judgment format that produced the pathology. A working skill yields denser, less-smooth prose, which a fluency-biased judge ranks *lower*: expected validity is negative. Admissible only as a one-sided harm guard: ON preferred proves nothing and is not reported; ON dispreferred below 20% triggers a readability investigation.
- **LLM judge with the fluency channel "blocked"** — **rejected.** The block cannot be verified without the ground truth being sought, and the documented bias operates on content amount (LLM graders score shorter, less-developed essays higher, arXiv:2603.23714), so blocking style does not block it.
- **Holistic human blind rating ("rate depth 1–7")** — **rejected in that form.** Naive human preference carries the same fluency channel; the evidence that humans beat auto-graders is about effortful *rubric verification*, not preference. Admissible only as criterion-referenced binary verification with ≥3 raters.
- **Adversarial/refutation judging** — accepted as candidate *generator*, rejected as *scorer*. Critics emit defects at a rate set by the prompt. If the defect taxonomy is the rule set restated, defect density is a compliance measure with a costlier instrument.
- **Mechanical depth proxies** — dead on arrival. The GRE AWA "Development" metric (log mean discourse-unit length) ranks Llama 4.428 above human 4.290; its own authors concede it does not capture analytical reasoning. Admissible only as a one-sided harm screen.
- **Bundle-level comprehension/transfer battery** — the only real benefit test available, **deferred by decision on 2026-07-16**. Requires naive readers, between-subjects, transfer and failure-prediction items only (no recall — fluency inflates recall and the feeling of understanding; transfer is where that illusion breaks). Not run. Its absence is why "benefit unverified" appears in the claim ceiling.

## The threat that survives every mitigation above

Every instrument affordable here measures whether the model obeys the rules. The one instrument that measures whether the prose got better — transfer — is the one deferred.

The surface rules will show large, clean effects, because those features are detectable *precisely because* reward training already optimizes them, and "an LLM follows explicit lexical instructions" was never in doubt. The exercise will produce a table and feel rigorous.

The failure mode is not wrong numbers. It is that a correct compliance measurement gets read, months later, as a quality verification — by us, in our own writeup, with no intent to deceive, because "A/B 검증했다" is what the artifact will look like. Field 15 is the only thing standing between those two readings.
